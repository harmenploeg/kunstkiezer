## Database en anonieme toegang

Live catalogusmetadata gecontroleerd:

- RLS aan op kk_profiles, kk_seen, kk_update_schedule en kk_update_runs.
- Profielen en bezoeken: authenticated CRUD, eigenaarcontrole via auth.uid() in zowel USING als WITH CHECK; geen anon-grants.
- Updateschema en uitvoeringen: beheerdercontrole in policies. Geen algemene schrijfgrants op uitvoeringen.
- Publieke beheer-RPC's zijn SECURITY INVOKER, lege search_path, geen anon-EXECUTE. De vertrouwde claim_update is niet uitvoerbaar door anon/authenticated. De private rolcontrole gebruikt SECURITY DEFINER met lege search_path.
- Anonieme REST-proeven met limit=0 op profiel, bezoeken en schema: HTTP 401. Leden-RPC: HTTP 404, geen toegang/resultaten. Ongeauthenticeerde delete-account-aanvraag zonder persoonsgegevens: HTTP 401.
- Supabase advisors: geen nieuwe bevinding. Bekend: gelekte-wachtwoordbescherming uit; drie informatieve meldingen over bewust afgesloten private tabellen zonder policies. Remediatie: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection.
